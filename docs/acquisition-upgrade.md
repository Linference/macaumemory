# 资料选图与多照片比对：技术使用说明

本轮修改保留现有地图、档案、语音和识别流程。新增 `capture.html` 选图工作台、识别页的多照片比对、人工审核清单及参考库草稿导入工具。本文说明已实现的行为，不是比赛研究计划或研究结果。

## 选图工作台

1. 在 `capture.html` 选择 JPG / PNG / WebP 照片，或读取影格文件夹。单批最多 500 张、800 MB。处理保留在当前页面，刷新后需重新读取。
2. 可读入同一 MacauSplat 工程生成的 `review-quality.json`，确认工程一致后启用。报告按文件名对应；工程指纹是来源记录，不能独立鉴别照片内容。
3. 选择 3 / 5 / 10 / 20 张预算。支持综合选图、均匀抽帧、随机对照、视觉差异和视角覆盖。所有方法共用同一可用照片过滤规则。
4. “分析影像差异”下载本地 DINOv2 ONNX（约 87 MB），验证模型 SHA-256 与参考库一致，使用整张照片的三裁切和翻转增强。可取消；保留已完成的向量。
5. 打开每张推荐照片，确认目标与建筑身份。若需要核对投影框，另行打开 MacauSplat 输出的 `qa.html`。此网页的确认不代表框位已做独立人工真值比较。
6. 选择建筑、填写真实拍摄批次及来源/使用权，导出 `reviewed-capture.json`。仅导出已逐张确认的照片清单，不包含图片本体。浏览器未下载时，可展开清单并复制保存。

“用真实建筑照片试一试”使用既有妈阁庙实拍资料。示范集合没有三维姿态，亦不能作为独立实拍识别评测。原有照片来源和授权随导出保留。

## 策略 acquisition-v1

优先级采用可解释的启发式：可靠性 ×（0.05 + 0.45 × 新视角组 + 0.35 × 视觉差异 + 0.20 × 候选接近指标）− 0.12 × 成本指标。选完一张后重新计算新视角/差异。

- 几何可靠性来自有效支持点、网格分布与二维点跨度；`review` 等级折减。不是可见表面比例、遮挡概率或标注准确率。
- 影像细节指标来自缩略图灰度梯度；纹理多不必然意味着目标清晰，需人工检查。无几何报告时只使用可获得的影像因素。
- 视觉差异是归一化特征与已选照片的最大余弦相似度转换。首次选择没有已有照片时使用起始值 1。
- 候选接近指标使用冻结参考库的视觉分差；最高分过低时不奖励。示范照片按原始文件名排除同名参考，但仍非独立评测。
- 修正成本当前是根据复核原因数量的估计，不是实际人工耗时。照片对话框记录打开至确认的经过时间，不能据此当作严谨的人因效率结果。
- `reject`、无报告对应的影格、零可靠性和字节重复照片被排除。不同编码器维度、无效向量直接报错。

未提供视角时界面显示未提供；24 个视角组不是完整覆盖率。所有阈值/权重尚待开发集验证，不能声称策略已经优于对照。

## 多照片比对

识别一张照片后，勾选拍摄同一建筑，点击“加入目前照片”。选择另一个角度、运行识别，再加入。最多 3 张，照片可移除，也可开始另一栋建筑。

使用完整候选库计算各张纯视觉分数，再平均排序。各张首位候选、原始分数和分差必须满足既有接受条件，且不能有极接近的特征，才显示共同支持；仍需核对地点。逐张冲突、低分与近重复不会升级成共同支持。不自动写入档案或修改当前单照片查重结果。

精确 SHA-256 重复会拒绝。不同文件/较低特征相似度不能证明拍摄视角独立；重新压缩或裁切仍可能绕过重复检查。平均分也不是正确概率。多照片规则尚未完成独立实拍校准。

## 审核后生成参考库草稿

先在工作台完成影像分析、逐张确认及来源填写，再保留原图运行：

```powershell
node tools/collection/import-reviewed.mjs --bundle "<reviewed-capture.json>" --photos "<原图文件夹>" --out "output/capture-import/<新批次>"
```

工具验证人工确认状态、建筑编号、批次、编码器 SHA-256/维度、原图 SHA-256，再输出图片、审核清单与 `memory-embeddings.draft.json`。已经存在的原始照片不算新增参考。不会自动改写公开参考库；需要在开发/验证流程中审核草稿再部署。清除过时的缓存原型及留一法数字，保留旧部署阈值并标记重新校准待完成。

手动选择既有记忆照片时，工具也按档案编号与实际文件哈希核对其原始来源，避免把本站的 WebP 转换版本再次计为新参考。任意改名、裁切和重压缩的近重复仍需人工核查。

如没有完成影像分析，仍可导出照片清单，但导入参考库工具会要求有效向量及编码器信息。不通过这份清单自动产生 YOLO 真值或训练神经网络。

## 选图对照工具

```powershell
node tools/collection/evaluate-selection.mjs "<dataset.json>" "output/selection-evaluation/report.json"
```

输入格式：`schemaVersion: 1`、`protocol: "full_image_three_crops_flip_tta"`、`encoder: {dim, onnx_sha256}`、开发数据确定并冻结的 `thresholds: {hit, maybe}`、`candidates`、`queries`。

每条照片需要 `id`、实际文件的 `sha256`、真实 `captureGroup`、人工 `buildingId` 和同一编码器 `vector`。候选可提供 `viewBin`、`imageQuality`、几何等级/支持值。`queries` 全部是独立测试照片，库外建筑也填写其真实编号，不能与候选池建筑编号混用。

工具阻断编号/字节哈希重复、候选与测试拍摄批次重叠。候选优先级只使用候选池，候选接近程度按候选池的批次留出计算。测试集不参与选图。比较 3 / 5 / 10 张预算，随机策略使用多个固定种子。缺失三维姿态时视角基线标记跳过。可用照片不足预算会标明。

输出纯影像 Top-1、库外误接受率、接受精确率、人工确认比例和选中清单。只覆盖特征检索，不验证 YOLO、重建精度、手机耗时、真实人工时间。没有独立实拍数据时不生成性能提升结论。近重复、拍摄者隔离、分组真实性需另行核查；同建筑/批次相关性需在正式分析中处理。

## 验证

新增测试验证选择非重复视角、统一过滤、随机可复现、无姿态提示、无效向量拦截、报告绑定字段、逐张确认导出、多照片冲突/近重复处理、原图/编码器校验、重复参考拦截和测试数据不影响选图。运行 `npm test` 与 `npm run build`。
