# 現場 90 秒 Demo 劇本（離線演示頁）

> 攤位實戰用。評審通常在你的攤位停留 **1~3 分鐘**，前 30 秒決定他會不會繼續問。
> 目標：**讓評審親手拍照**，然後在 10 秒內看到它變成地圖上的一個永久編號。

---

## 一、90 秒逐秒劇本

按「▶ 開始 90 秒示範」後照著講（頁面會自己跑完 5 幕）。

| 秒 | 畫面 | 你要說的話（照念即可） |
|---|---|---|
| 0–10 | 地圖上已有兩個記憶點，旁白金框出現 | 「澳門有上千棟有故事的建築。我們做的不是拍照 App——**我們給每一棟建築一個永久編號**，就像用深度學習幫流浪貓做臉部辨識，只是對象換成建築。」 |
| 10–32 | 手機面板出現大三巴照片，六步流程逐一亮起：EXIF → 人物偵測 → CLIP 嵌入 → **地理先驗** → 相似度 → 建檔 | 「現在我在大三巴前面拍一張。手機自動讀到 GPS（22.1975, 113.5408）。系統先看 **90 公尺內有沒有既有記憶點**——有的話才需要比對。這是關鍵：**先用地理把候選縮到 1 個，再用視覺確認是不是同一棟**。」 |
| 32 | 判定卡：**併入既有記憶點 MM-0001**，餘弦相似度 0.903 | 「同一個角度換一張，相似度 0.903，超過 0.86 的門檻 → 自動併入 **同一個編號 MM-0001**，時間軸多一張。評審您看，**這棟樓永遠是同一個號**。」 |
| 32–54 | 第二張照片：澳門科學館 | 「換一棟——澳門科學館。這次 90 公尺內沒有候選，所以直接**建立新記憶點 MM-0004**，並由 DeepSeek 寫出建築解讀。」 |
| 54–70 | 第 4 幕：閾值說明 | 「為什麼門檻是 0.86？我們用 7 個模型、20 個視角、140 張受控影像量出來的：**同一棟換角度 0.90 ± 0.04、不同棟 0.76 ± 0.07，AUC 0.950**。0.86 剛好落在兩者的空隙。」 |
| 70–90 | 第 5 幕：三間度假村出現金色 90 m 圈 | 「那什麼會錯？**全部錯在路氹城三間長得像的度假村之間**——倫敦人被認成銀河的比率高達 72%。但這三棟相距至少 296 公尺，**90 公尺的地理先驗一次把它們全部排除**。所以我們的設計是：**視覺只負責同一棟的不同角度，地理負責『不可能是我』**。」 |

收尾一句（一定要說）：

> 「我們把整個系統、資料與評測腳本都開源在 GitHub，**掃這個 QR code 就能自己玩**。
> 目前實拍資料集正在建立，這也是我們下一步要驗證的。」

## 二、評審一定會問的問題（照這樣答）

| 問題 | 回答（誠實版） |
|---|---|
| 這跟 Google Lens 有什麼不同？ | Lens 是做通用物體辨識；我們的目標是**為建築建立可累積的永久身分**，並把「地理先驗 + 視覺驗證」變成可量測的決策流程。而且我們**不需要訓練資料**、全部使用開放資料。 |
| 準確率多少？ | 受控多視角 **AUC 0.950**（閾值 0.86 時認出率 86.1%、誤判率 12.2%）；換角度／光線後 AUC 降到 **0.850**；真實照片的驗證正在進行，這是我們誠實標示的限制。 |
| 你怎麼知道不是運氣好？ | 每組數字都有 ROC、AUC 與配對數；140 張受控影像、330 組正樣本、1440 組負樣本，種子固定、一條指令可重跑。 |
| CLIP 分類建築風格準嗎？ | **不準**——我們實測 top-1 只有 **2.8%**。所以我們**刻意不用 CLIP 判風格**，分類交給地理先驗（最近的 OSM 建築／景點），CLIP 只負責「是不是同一棟」。這個失敗是我們的實驗結論之一。 |
| 為什麼不用 YOLO 訓練分類器？ | YOLO 是物件偵測器，COCO 沒有「葡式建築／騎樓」這些類別，要自己標幾百張。CLIP 零樣本可以**改文字就換類別**，對公民科學式的建檔更實際。 |
| 照片裡有人怎麼辦？ | 產線會用 YOLO 偵測人物並**自動模糊人臉**，只保留建築；我們不儲存任何可識別個人的資訊。 |
| 資料量會不會太少？ | 目前受控實驗 140 張、7 棟建築；實拍資料集正在建立中（8 棟 × 每棟 3~5 張）。我們**沒有宣稱**在真實世界已達到的準確率。 |
| 同一棟不同角度真的認得出來？ | 同一棟換角度平均 0.901，5% 分位 0.840；我們用 **0.86 併入 / 0.80 標記待複核** 的兩段式決策，低信心的進人工複核佇列。 |
| 你的創新點是什麼？ | 三點：① 把 VPR（視覺重辨識）跨域用到文化遺產建檔並做成公眾平台；② 地理先驗 + 視覺相似度的兩段式融合決策，並用實驗證明它能消除全部的相似建築誤判；③ 全開放資料與零成本工具鏈，30 秒完成建檔。 |
| 未來怎麼擴大？ | ① 實拍驗證與更多建築；② 影像編碼器換成 DINOv2 提升重辨識；③ 記憶點時間軸與人工複核 UI；④ 開放公眾拍照上傳，累積澳門建築的數位記憶。 |
| 這跟 TECA（科技促進藝術）有什麼關係？ | 它讓**每一棟沒有被記錄的建築**都能進入一個公開、可累積的文化檔案；技術上我們也把 3D 掃描文物（唐三彩、青花扁瓶）做成可在瀏覽器裡翻轉觀看的模型。 |

## 三、故障預案

| 情況 | 處理 |
|---|---|
| 筆電當機／沒電 | 立刻改播**錄屏 MP4**（手機裡也存一份），同時口述劇本 |
| 網路斷 | **不用擔心**——演示頁是離線的（照片與資料都內嵌）；這是它存在的理由 |
| 投影解析度差 | 按 **D** 隱藏答辯細節、按 **F** 全螢幕；只留三個面板與旁白 |
| 評審想自己操作 | 按**空白鍵**逐步前進（不要自動播放），讓他掌控節奏 |
| 評審問到沒準備的數字 | 打開展板掃 QR 進線上版，或直接說「這個數字在我們的評測報告裡，我現在調出來」→ 開 `tools/eval/out/report.md` |

## 四、人員分工（團隊項目）

| 角色 | 任務 |
|---|---|
| 操作手 | 控制頁面（空白鍵／D／F）、必要時重播 |
| 講解者 | 照第一節劇本講，眼睛看評審不要看螢幕 |
| 實拍手 | 拿手機請評審「挑一棟建築拍一張」，製造互動（最有記憶點的一刻） |
