# tools/eval —— 建築記憶點的重辨識評測

這一套是為了**答辯與展板**而寫的：把「拍照 → 自動歸戶」這件事拆成可量測的實驗，
每個數字都能一條指令重跑出來。

## 一鍵重現

```powershell
cd 'D:\Users\LINKIT\Desktop\澳门记忆'
python tools\eval\render_views.py        # 1) 7 個 GLB 模型 × 20 視角 = 140 張受控渲染圖
python tools\eval\build_dataset.py       # 2) 彙整資料集清單（含實拍目錄掃描）
python tools\eval\evaluate.py            # 3) CLIP 嵌入 + 全部指標 + 圖表 + 報告
python tools\eval\analyze_errors.py      # 4) 誤判來源分析 + 地理先驗分析
```

結果在 `tools/eval/out/`：`report.md`、`metrics.json`、`fig-*.png/svg`（可直接上展板）、
`pairs_*.csv`（每一對配對的相似度，可審計）。

## 為什麼要自己渲染（而不是用現成資料集）

1. 需要**同一棟建築、可控地改變視角**的正樣本 → 沒有現成資料集能同時滿足「澳門建築 + 已知角度」。
2. 沙箱禁止程式建立具名管道，headless Chrome 起不來 → 改用 **VTK 離屏 OpenGL**（`render_views.py`），
   在同一個行程內渲染，速度快（140 張約 15 秒）、完全離線、可重現。
3. **誠實性**：渲染圖會明確標記為 `render-*`，與實拍 `real-phone` 分開統計，
   報告裡也寫明渲染影像不是真實照片。

## 資料集分層（dataset.csv 的 tier 欄）

| tier | 來源 | 用途 |
|---|---|---|
| `render-base` | GLB 渲染，同環境環繞 12 方位角 | 主實驗（最乾淨的受控條件） |
| `render-cond` / `render-cond2` | GLB 渲染，改變仰角／距離／光照 | 跨條件實驗（模擬不同時間、天氣重拍） |
| `demo-map` | 既有 3D 地圖截圖 | 跨呈現方式比較 |
| `demo-crop` | 舊流程用同一張圖裁切的「第二張」 | **資料洩漏對照組，主實驗排除** |
| `real-phone` | 使用者手機實拍（`photos-src/real/<id>/`） | 真實世界驗證（見 `SHOOTING.md`） |

## 實驗設計

| 代號 | 問題 | 判準 |
|---|---|---|
| E1 | 同環境不同視角，能不能認出同一棟？ | AUC、0.86 閾值下的認出率／誤判率 |
| E1b | 文物（唐三彩、青花扁瓶）也適用嗎？ | 同上 |
| E2 | 換角度、換距離、換光線之後還認得出嗎？ | AUC 下降幅度 → 實拍情境的預期 |
| E3 | 文物會不會被誤併進建築的記憶點？ | 跨類別超過閾值的比例 |
| E4 | 3D 渲染與地圖截圖可以互相匹配嗎？ | 跨域相似度（域偏移的量測） |
| E5 | 舊流程的「同棟第二張」有多可信？ | 裁切圖 vs 真實多視角的相似度對比 |
| E6 | CLIP 零樣本分類能不能取代人工標類？ | top-1 準確率、混淆矩陣 |

## 方法上的兩個要點

1. **相似度**：CLIP ViT-B/32 影像向量（L2 正規化）的餘弦相似度，乘上模型學到的 `logit_scale` 才做 softmax。
2. **分類聚合順序**：`pipeline.py` 目前是「先對所有提示詞 softmax，再依類別平均」，
   這會讓提示詞條數多的類別佔便宜；`clip_embed.py` 實作的是業界標準做法
   （**先依類別平均相似度，再對類別 softmax**），`evaluate.py` 會同時輸出兩種結果以量化差異。

## 已知限制（報告中已載明）

- 渲染影像 ≠ 真實照片；E1/E2 的結論是「受控條件下的上界」，真實數字必須由 `real-phone` 驗證。
- 分類實驗（E6）目前只涵蓋 3 個真實類別，樣本不足以宣稱 12 類準確率。
- 測試建築僅 5~7 棟，路氹城度假村群佔比高，會放大「相似建築互認」的難度。
