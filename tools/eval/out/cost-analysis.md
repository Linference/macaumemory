# 成本分析：端側識別 vs 雲端 API

查詢日期：2026-11-02。價格以官方頁面為準，引用前請再核對。本文件由 AI 程式助手（Claude）協助整理，數字解讀由研究者負責。

## 每 1,000 次識別的直接費用

| 方案 | 每 1,000 次 | 依據 |
|---|---|---|
| 途見端側識別（瀏覽器內 DINOv2 + YOLO） | **伺服器運算 0 元** | 運算在使用者裝置上完成，伺服器只提供靜態檔案 |
| Google Cloud Vision 地標偵測 | 首 1,000 次／月免費；之後 **US$1.50**（1,001–5,000,000 次），超過 500 萬次 US$0.60 | Google 官方定價頁（含示例：每月 5,300 次 = US$6.45） |
| Azure AI Vision 影像分析 | 官方頁面未顯示金額；第三方資料約 €1／1,000 次，免費層 5,000 次／月 | 需登入 Azure 定價計算機確認，**不建議引用** |

## 端側方案的真實成本：模型下載流量

端側方案不是「完全免費」，成本轉移到「首次下載模型」：

| 項目 | 大小 |
|---|---|
| DINOv2 ViT-S/14（fp32 ONNX） | 87.2 MB |
| YOLO 建築偵測（ONNX） | 38.0 MB |
| 合計（首次使用，之後由瀏覽器快取） | **125.2 MB／每位新使用者** |
| 若改用 int8 量化版 DINOv2 | 見 `extended.json` 的 int8 結果（準確率與大小對照） |

因此：使用者識別次數越多，端側方案越划算；一次性、只拍一張的使用者，下載 125 MB 反而是負擔。可行的折衷是 int8 模型或只在使用者主動開啟識別時才下載。

## 限制

- 雲端地標偵測只認得全球知名地標，**無法辨識澳門的普通建築**，也不能接入途見的參考庫；此處只作為「雲端計費」的成本參照，不是功能等價的替代方案。
- 未計入網站靜態託管與流量費用，其金額取決於託管服務與使用量。
